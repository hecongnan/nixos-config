# Niri 窗口暂存区

通过 Niri IPC 将任意现有窗口暂存到命名工作区 `scratch`，不启动新应用，
窗口的程序和内容保持运行。呼出时临时悬浮在当前工作区上，不挤动背景平铺窗口，
默认区域采用最初在本机实际呼出的窗口大小：954×1028，居中显示，约半屏宽。
原始补丁没有固定尺寸；这里显式固定初始尺寸，避免继承最大化应用的整屏大小。
循环切换时，下一窗口沿用当前悬浮窗的
位置和大小。拖动或缩放后，后续切换沿用调整后的区域。收起后恢复各窗口
原来的浮动位置、大小及平铺／浮动模式。
原本浮动的窗口保持浮动，原本平铺的窗口只在呼出期间临时浮动。
初始缩放最多等待 0.5 秒；客户端未确认时不按旧尺寸居中、不保存旧尺寸，
并保留待完成状态，在后续呼出或重新聚焦仍浮动的窗口时重试。

本仓库的 `Mod` 是 Super（Win 键）。

| 快捷键 | 操作 |
| --- | --- |
| Super+Shift+反引号 | 收起当前窗口 |
| Super+反引号 | 呼出最近收起的窗口；聚焦后再按则收起 |
| Super+Ctrl+反引号 | 循环呼出下一个窗口 |

呼出的窗口失去焦点时，切换快捷键只重新聚焦它，不重新插入平铺列或调整位置；
即使用户已将它手动改回平铺，也不强制转回浮动；再按一次才收起。循环切换会收起上一个窗口，即使它已失去焦点，也不会叠出多个窗口。
呼出窗口收起后，会在原窗口仍存在且未移走时恢复之前的焦点，
不修改其他窗口的平铺／浮动模式、尺寸或排列。
支持跨显示器呼出。`scratch` 是普通工作区，会出现在 Overview、工作区列表和
上下切换中，并影响数字工作区索引。自动模式在按键所在工作区直接呼出，即使该工作区名为 `scratch` 也不跳转；
手动模式从暂存区呼出时仍先返回普通工作区。收起最后一个窗口导致原工作区消失时，也会自动保持在普通工作区。
仍可使用原有窗口移动操作直接移出。

## 自动循环其他工作区窗口（本机已启用）

`toggle` 和 `next` 支持 `--all-workspaces`：

```sh
python3 "${XDG_CONFIG_HOME:-$HOME/.config}/niri/scratchpad.py" toggle --all-workspaces
python3 "${XDG_CONFIG_HOME:-$HOME/.config}/niri/scratchpad.py" next --all-workspaces
```

本机在 `home/aurora/scratchpad.nix` 的 `toggle` 和 `next` 命令中启用该参数；
`stash` 仍可手动指定成员，其他工作区的普通窗口会自动进入循环候选。
上游基础版本：`hecongnan/niri-scratchpad@9d2acdf`。保留本机 `d78eefc` 的延迟尺寸确认和只聚焦修复。

- 自动发现其他工作区（包括其他显示器）的窗口，无需逐个手动收起；当前工作区的普通窗口不加入候选列表。
- 保留手动暂存的成员，新开或关闭的窗口会在下次按键时更新。
- 自动借用的窗口在收起或切换时返回原工作区，恢复原来的平铺／浮动模式和已记录的尺寸；手动暂存成员仍返回 `scratch`。
- 在呼出窗口上主动执行 `stash`，会把它改为手动暂存成员；`release` 则保留当前位置并解除恢复记录。
- 无名的来源工作区借用期间会临时命名为 `scratchpad-return-…`，以免移走最后一个窗口后被 Niri 删除；窗口归还或关闭后，下次调用脚本会清理临时名称。用户另行设置的名字不会被覆盖。
- 平铺窗口归还时重新加入布局，不保证恢复其原来的列顺序、分组或自动高度分配策略；浮动位置和实际尺寸仍受应用与显示器约束。
- 若来源工作区因显示器移除等原因确实不存在，窗口退回可访问的 `scratch`，并在标准错误中说明；运行时状态丢失后无法恢复借用前的工作区信息。

将当前聚焦的窗口移出暂存管理：

```bash
python3 ~/.config/niri/scratchpad.py release
```

窗口保持当前位置及当前平铺／浮动状态，Super+Shift+V 可手动切换模式。
状态保存在 `$XDG_RUNTIME_DIR/niri-scratchpad-*.json`，按 Niri socket 区分会话，
不依赖后台守护进程。丢失状态后仅从暂存工作区恢复成员；退出 Niri 后不保留。

Home Manager 通过 `home/aurora/scratchpad.nix` 部署脚本和 `scratchpad.kdl`，
`assets/niri.kdl` 加载该片段。按仓库正常 build/switch 流程应用配置后生效。

验证：`python3 tests/test-scratchpad.py`；Flake 检查项：
`nix build .#checks.x86_64-linux.scratchpad --no-write-lock-file`。

自动模式不会把当前工作区的普通窗口加入候选；临时借入 `scratch` 的窗口也不会被误登记为手动暂存成员。
